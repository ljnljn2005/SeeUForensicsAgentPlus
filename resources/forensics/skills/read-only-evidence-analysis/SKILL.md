# 只读取证分析（read-only-evidence-analysis）

## 原则

- **不写原始证据**：所有解析、解包、转换的输出落到独立工作目录（例如 `<workdir>/derived/`）。
- **先哈希后分析**：对每个证据文件先算 SHA-256（必要时 SHA-1/MD5 仅用于与外部情报对齐），把哈希写进报告。
- **可复现**：报告里的每条命令都应是只读命令，且注明工具版本与参数。
- **区分事实/推断**：工具输出是事实；对输出的解释是推断，必须标注置信度。

## 标准流程

1. 清点：列出目标文件/目录，记录路径、大小、时间戳（标注时区）。
2. 哈希：`sha256sum`（Linux）/ `Get-FileHash -Algorithm SHA256`（Windows）；大文件分批并记录。
3. 识别：`file`、扩展名与魔数比对、`stat`；对镜像记录分区表信息。
4. 只读查看：
   - 文本/日志：分页只读，避免 `less` 写入历史；日志解析输出到派生目录。
   - 二进制：`strings -a`、十六进制查看、静态解析（不执行）。
   - 压缩/归档：先列出清单（`unzip -l`、`7z l`），解包到派生目录，记录清单哈希。
5. 检索：按 IOC（路径、域名、IP、哈希、注册表键）在副本上检索，保留命中位置。
6. 输出：按 `evidence-chain-report` 结构交付；派生文件与原始证据建立映射表。

## 安全边界

- 不执行可疑二进制/脚本；需要动态分析时先向用户说明虚拟机隔离方案并取得确认。
- 不修改证据的访问时间（需要时优先用镜像/副本；无法避免时记录该影响）。
- 不在证据目录内创建临时文件、锁文件、索引文件。
- 涉及删除、覆盖、上传、外传的操作一律先列清单并等待显式确认。

## 交付自查

- [ ] 每个分析对象都有 SHA-256 与采集时间
- [ ] 所有派生文件都在独立目录，且有原始 → 派生的映射
- [ ] 报告命令均为只读、可复现
- [ ] 未执行任何样本，未修改原始证据
- [ ] 结论与推断分区，缺失信息已列为待补充证据
