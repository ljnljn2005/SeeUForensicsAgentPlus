# 取证报告自动生成 Skill

> 把分散在各技能里的 Findings 收敛成一份可提交/可归档的取证报告。对接美亚超级取证大师，
> 自动拉取案件与检材元数据，套用模板产出。

---

## 0. 合规基线

- 报告须含：案件信息、检材信息（含 hash）、分析过程、证据链、结论、合规声明。
- 合规声明模板：「本报告仅依据授权范围内获取的电子数据制作，结论受检材完整性与分析局限约束，
  异常/关联不构成单独定罪依据，须结合其他证据综合判定。」
- 个人信息脱敏（参照 资金分析-通用 的脱敏规则）。

| 来源 | 调用方式 | 说明 |
|------|----------|------|

| 资金分析交付物 | `./.../资金分析报告.html` | 资金链路 |

## 2. 使用方法

```bash
# 套用模板生成空报告骨架（供人工/AI 填充）
python assets/build_report.py --case 「案件名」 --output 「输出目录」
```
或直接加载模板 `references/report-template.md` 由 AI 按证据填充。

**对接 MYOS（myos-forensics-mcp）**：先调用 MCP 工具检索案件列表与证据项，
把返回的案件编号、检材清单、解析摘要写入报告「案件信息/检材信息」节；再汇总其他技能交付物填入「分析过程/证据链/结论」。

---

## 3. 报告结构（章节顺序）

1. 封面/案件信息（案件编号、委托方、分析人、日期）
2. 检材信息（来源设备、采集时间、原始 hash、只读声明）
3. 分析环境与工具（Volatility3/IDA/YARA 等版本）
4. 分析过程（按技能分节：内存/样本/IOC/资金）
5. 证据链（Evidence→Finding→Path，引用各技能 Finding ID）
6. 结论与建议（家族/归因/处置建议）
7. 合规声明与局限性
8. 附录（IOC 清单、哈希表、命令记录）

---

## 4. 联动规则

- 收到"生成报告"时，先问清案件名与要纳入的技能交付物目录；缺则按 §1 表格自动探测。
- 证据链章节必须引用上游技能的 Finding ID，禁止凭空结论。
- 多案件/多嫌疑样本用 `references/report-template.md` 的多检材变体。

## 适用场景

本技能用于电子数据取证项目进入结果固定与报告输出阶段，将内存取证、恶意样本初筛、C2/IOC 归因、资金分析等分散发现收敛为可提交、可复核、可归档的取证报告。

### 典型实战场景

1. 竞赛/CTF 取证答题输出：需要按题目要求输出答案、证据路径、哈希、命令日志、时间线，避免只有结论没有证据。
2. 案件复盘与内部报告：将美亚超级取证大师（MYOS）解析结果、人工分析结论、工具输出整合成案件小结。
3. 委托取证/司法鉴定辅助报告：在授权范围内形成包含检材信息、原始哈希、分析过程、证据链、合规声明的结构化报告。
4. 跨检材关联分析：同一案件包含手机镜像、硬盘镜像、内存镜像、流量包、数据库、云数据时，需要统一证据表和时间线。
5. 攻击事件调查：需要输出攻击链路图、IOC 清单、进程/文件/网络/持久化证据，并支持后续处置与溯源。
6. 资金/涉诈案件：需要把钱包地址、交易哈希、账户关系、聊天内容、登录痕迹形成闭环证据。

### 触发方式

当用户提出「生成取证报告」「案件小结」「证据报告」「MYOS 报告」「美亚报告」「证据链整理」「输出证据清单」等诉求时，应启用本技能。

### 适用前提

- 已获得合法授权，或属于竞赛/教学环境中允许分析的样本与检材。
- 检材来源、提取时间、封存状态、哈希值可追溯；优先使用只读镜像或只读挂载。
- 上游分析结果已有 Finding ID、命令记录、截图/日志或工具导出文件。
- 需要明确报告受众：竞赛裁判、侦查人员、检察官、法官、安全运营团队、内部审计。

### 不适用或需谨慎场景

- 仅有截图、口头描述或无法复现的结论，不能直接生成正式取证报告。
- 检材哈希不一致、镜像损坏、时间未校准、分析环境被污染时，应先停止报告生成并标记证据风险。
- 涉及个人隐私、密钥、口令、资金账户时，必须脱敏；未脱敏版本仅限授权范围内部流转。

### 专家经验

- 报告不是写出来的，而是证据组织出来的：每个结论必须能落到文件、命令、哈希、时间戳和解释逻辑。
- 多检材案件优先建立统一证据编号，避免不同检材之间出现同名文件、同名账号、同时间事件混淆。
- 时间问题是取证报告最常见翻车点：必须写明原始时间、时区、转换后时间、转换工具/规则。

## 输入输出说明

### 输入说明

本技能输入分为案件输入、检材输入、工具输入、人工输入四类。所有输入必须能追溯到来源、时间和完整性校验方式。

#### 1. 案件与委托输入

| 字段 | 必填 | 说明 | 实战要求 |
|---|---:|---|---|
| 案件编号 | 是 | 委托方或竞赛平台编号 | 用于报告页眉、证据包命名、附录索引 |
| 案件名称 | 是 | 可简写但不得歧义 | 多案件并存时区分主案/串案 |
| 委托事项 | 是 | 需要证明的问题 | 避免超出委托范围作结论 |
| 授权范围 | 是 | 可分析的检材、账号、时间段 | 无授权内容标记为不可用 |
| 接收时间 | 是 | 检材接收/下载时间 | 精确到分钟，建议含时区 |
| 保管链 | 建议 | 移交人、接收人、封存状态 | 用于证据可采性说明 |

#### 2. 检材输入

| 字段 | 必填 | 说明 |
|---|---:|---|
| 检材编号 | 是 | 如 E01、E02，必须全局唯一 |
| 检材类型 | 是 | 磁盘镜像、手机镜像、内存镜像、流量包、数据库、日志、云数据 |
| 原始文件路径 | 是 | 原始证据存放位置 |
| 文件格式 | 是 | E01/AFF4/DD/VMDK/PCAP/SQLite/MySQL dump 等 |
| MD5 | 条件必填 | 竞赛/实战建议至少 MD5 或 SHA256 二选一 |
| SHA256 | 条件必填 | 正式报告建议同时记录 MD5 与 SHA256 |
| 采集时间 | 是 | 原始采集时间，注明时区 |
| 只读状态 | 是 | 是否只读挂载、是否写入屏蔽、是否使用写保护 |
| 解密/挂载结果 | 条件必填 | 若涉及 BitLocker/LUKS/加密容器，记录密钥来源、挂载点、解密后哈希或卷哈希 |

#### 3. 工具与数据源输入

| 来源 | 输入形式 | 报告用途 |
|---|---|---|
| MYOS/美亚超级取证大师 | MCP 查询结果、案件编号、检材清单、解析摘要 | 案件信息、检材信息、解析结果引用 |
| 内存取证 | findings.md、Volatility3 输出、进程/网络/模块/注册表导出 | 运行时证据、攻击过程 |
| 样本初筛 | 初筛表.csv、YARA 命中、PE 元数据、壳/能力标签 | 恶意样本结论 |
| C2/IOC 归因 | ioc-export.csv、attribution-report.md | IOC、家族、基础设施 |
| 资金分析 | 资金分析报告、交易流水、地址聚类 | 资金链路、账户关联 |
| 人工勘验 | 截图、命令记录、聊天记录导出 | 辅助证据，须注明来源文件 |

#### 4. 人工补充输入

- 时区规则：检材本地时区、服务器时区、UTC、北京时间转换规则。
- 账号映射：昵称、UID、手机号、邮箱、钱包地址、设备号的对应关系。
- 密码/密钥来源：必须记录提供人、提供时间、验证结果；禁止在报告中明文展示高敏密钥，可用前后四位掩码。
- 题目/委托特殊格式：竞赛答案格式、字段名、是否要求英文、是否要求附截图。

### 输出说明

本技能最终输出不是单一文档，而是一组可复核交付物。若与既有项目目录冲突，优先保留原目录，新增 report_pack/，冲突字段标记为待人工裁决。

#### 1. 输出物清单

| 输出物 | 格式 | 用途 |
|---|---|---|
| 取证报告主文件 | Markdown/HTML/PDF | 正式报告 |
| 证据清单 | CSV/Markdown 表 | 逐项列明证据编号、来源、哈希、路径 |
| 跨检材关联表 | CSV/Markdown 表 | 支撑多检材证据链 |
| 时间线表 | CSV/Markdown 表 | 还原事件顺序 |
| 证据闭环表 | CSV/Markdown 表 | 每个答案/结论的证据来源与验证方式 |
| IOC/哈希/命令附录 | CSV/TXT/MD | 便于复现与导入平台 |
| 报告打包目录 | ZIP/目录 | 归档与提交 |

#### 2. 推荐目录结构

```text
report_pack/
  00_report/
    forensic_report.md
    forensic_report.html
  01_evidence/
    evidence_list.csv
    hash_manifest.csv
    cross_media_link.csv

  02_findings/

    triage_findings.csv
    ioc_export.csv
    fund_flow.html
  03_commands/
    command_log.md
    tool_versions.txt
  04_appendix/
    screenshots/
    raw_exports/
```

#### 3. 输出字段最低要求

- 每个证据项必须有：证据编号、检材编号、文件路径/数据库表、字段值、时间戳、哈希、验证方式、结论。
- 每个结论必须有：结论编号、对应问题、直接证据、辅助证据、排除项、置信度。
- 每个时间必须有：原始时间、时区、转换后时间、转换规则。
- 每个哈希必须有：算法、计算对象、计算工具、计算时间。

#### 4. 输出质量门槛

- 报告结论不得仅凭单一日志、单一截图或单一工具告警形成。
- 关键结论至少满足一项直接证据加一项辅助证据，或两项独立来源证据相互印证。
- 无法复现的结果必须标注为待复核，不得写成确定结论。
- 涉及账号归属、攻击者身份、资金去向时，必须区分技术关联与身份认定。

## D2-04 输出规范与证据闭环

### 设计目标

- 输出必须可提交竞赛、可入卷归档、可被第三方复核。
- 每个答案或结论必须能回溯到检材、文件、命令、哈希、时间转换方式和验证依据。
- 报告不仅呈现结论，还要呈现证据如何被固定、如何被解释、如何被交叉验证。

### 1. 文件哈希与证据清单模板

| 证据编号 | 检材编号 | 证据类型 | 文件路径/数据库表 | 字段/内容摘要 | MD5 | SHA256 | 时间戳 | 提取命令/工具 | 验证方式 |
|---|---|---|---|---|---|---|---|---|---|
| EV-001 | E01 | 磁盘镜像 | /evidence/disk.E01 | 原始镜像 | 填写 | 填写 | 采集时间 | 写保护设备/取证工具 | 哈希复核 |
| EV-002 | E01 | 浏览器记录 | /data/browser.db | visits 表 URL | 填写 | 填写 | 记录时间 | sqlite3 导出 | 原始库复查 |
| EV-003 | M01 | 内存进程 | /mem/memory.raw | 进程列表 | 填写 | 填写 | 内存采集时间 | Volatility3 | 多插件交叉 |

要求：证据编号必须全局唯一；同一文件在不同检材中出现时，不得复用同一证据编号。

### 2. 答案/结论闭环模板

| 答案编号 | 问题/委托事项 | 结论 | 来源文件 | 命令输出 | 哈希 | 挂载/解密结果 | 时间转换方式 | 多源验证依据 | 置信度 |
|---|---|---|---|---|---|---|---|---|---|
| A-01 | 是否存在远控样本 | 存在 | /triage/suspicious.exe | YARA 命中记录 | 填写 | 只读挂载 | 原始本地时间转 UTC | 样本字符串、网络 IOC、内存进程 | 高 |
| A-02 | 资金是否转入嫌疑人账户 | 技术关联成立 | /fund/flow.csv | 交易查询结果 | 填写 | 解密后数据库 | 链上时间转北京时间 | 聊天记录、登录账号、交易哈希 | 中/高 |

要求：关键答案不得只写最终值，必须保留来源文件、命令输出摘要和验证路径。

### 3. 跨检材关联表模板

| 关联编号 | 检材ID | 证据类型 | 文件路径 | 哈希 | 时间戳 | 账号 | 密码/密钥复用 | 聊天内容 | 数据库记录 | 流量命中 | 结论 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| L-01 | E01 | 文件 | /home/user/a.exe | 填写 | 填写 | 无 | 无 | 无 | 无 | 无 | 样本落盘 |
| L-02 | P01 | 聊天 | /phone/chat.db | 填写 | 填写 | 昵称/UID | 无 | 涉及地址 | 无 | 无 | 账号关联 |
| L-03 | N01 | 流量 | /net/capture.pcap | 填写 | 填写 | 无 | 无 | 无 | 无 | C2 域名 | 网络行为关联 |

要求：跨检材关联必须写明关联依据，不得仅因同名账号或相近时间直接认定同一主体。

### 4. 时间线表模板

| 事件编号 | 原始时间 | 时区 | UTC 时间 | 北京时间 | 事件类型 | 检材 | 路径/来源 | 关联账号 | 说明 |
|---|---|---|---|---|---|---|---|---|---|
| T-01 | 2026-01-01 03:10:00 | UTC+8 | 2025-12-31 19:10:00 | 2026-01-01 03:10:00 | 文件创建 | E01 | /tmp/payload.bin | 无 | 需与日志时间互证 |

要求：所有时间线必须先做时区归一；若系统时间、文件时间、应用时间、链上时间来源不同，必须分别标注，不得混用。

### 5. 攻击链路图输出要求

报告应至少给出文本版攻击链路，必要时附 Mermaid 图。文本版示例：

初始访问 -> 载荷下载 -> 进程执行 -> 持久化 -> C2 通信 -> 凭据获取 -> 横向移动/资金转移/数据外传。

每个节点必须标注：证据编号、时间、检材、工具依据。无法确认的节点标注为疑似。

### 6. 正向命中与反向排除模板

| 结论 | 直接证据 | 辅助证据 | 排除项 | 格式归一化 | 复现命令/脚本 |
|---|---|---|---|---|---|
| 样本为远控木马 | YARA 命中、C2 字符串、导入表特征 | 编译时间、壳特征、网络行为 | 排除正常远控工具合法使用场景 | 哈希统一小写，时间统一 UTC | yara -r rules sample |
| 账号与嫌疑人关联 | 登录日志、聊天账号、手机号绑定 | 设备指纹、IP 登录记录 | 排除公共设备、代理、账号被盗 | 手机号脱敏，UID 保留 | 数据库查询脚本 |

要求：正式报告不能只写正向命中，必须说明已排除的合理怀疑，尤其是合法工具、误报、共享设备、时区误差等情形。

### 7. 证据闭环规则

- 每个答案至少有一个直接证据；关键答案必须有多源验证。
- 命令输出必须保存原文或截图，并记录命令、参数、工具版本、执行时间。
- 数据库证据必须记录库文件哈希、表名、主键或 rowid、字段值、导出方式。
- 聊天记录必须记录账号、会话 ID、消息 ID、本地时间、原始文件路径。
- 资金交易必须记录交易哈希、链或平台、地址、金额、时间、确认数。
- 解密/挂载证据必须记录密钥来源、挂载点、是否只读、解密后对象哈希。
- 时间转换必须记录原始时间、时区、转换后时间、转换规则或工具。

### 8. 常见陷阱与规避方法

- 只看文件名不看内容：必须解析文件内容并记录哈希。

- 多检材证据编号重复：使用 EV-、L-、T-、A- 等前缀加全局序号。
