# 图像伪造检测器

通过多维启发式分析检测图片是否被伪造、篡改或AI生成。

## 使用方法

```bash
python scripts/detect.py <图片路径或URL>
```

脚本接受本地文件路径或URL。输出为JSON格式的详细分析结果。

## 检测流水线

### 1. 元数据检测
解析JPEG段（EXIF、JFIF、Adobe标记）和PNG文本块（tEXt、iTXt、eXIf）。标记以下内容：
- 已知编辑软件关键词（Photoshop、GIMP、美图等）
- AIGC/内容溯源签名（Label=1、ContentProducer、doubao等）

### 2. JPEG压缩分析
- 量化表与标准亮度表匹配，估算质量
- 8x8块边界分析（"块效应"），检测二次压缩伪影

### 3. 全局视觉特征
- 亮度均值/标准差、饱和度、调色板密度、直方图峰值
- 检测：异常亮度、过饱和、纹理匮乏区域

### 4. 局部特征分布
- 基于Sobel的角点类特征检测（4×4网格）
- 标记：特征密度低、过度集中、分布不均

### 5. 截图特征检测
- 宽高比与常见屏幕分辨率对比
- 边缘密度、文本行比例、纯色区域比例
- 识别：截图、屏幕录制、微信转发图片

### 6. 文档/纸质件篡改检测
- 纸张区域分割（亮度>=0.58，饱和度<=0.28）
- 逐块标准差→纹理一致性分析
- 可疑块比例、聚类指标（泛洪填充连通分量）
- 文本行波动分析
- LBP（局部二值模式）相邻块间纹理不一致性
- 梯度方向不一致性分析
- 通过拉普拉斯方差检测噪声不一致性
- 通过JPEG重新编码进行ELA（错误级别分析）

### 7. 决策引擎
将证据信号分为三个类别：

| 状态 | 描述 |
|------|------|
| `有伪造` | 检测到强篡改信号 |
| `待确认` | 可疑但未达强阈值 |
| `截图` | 干净的截图，无篡改 |
| `无伪造` | 未发现显著异常 |

## 输出字段

| 字段 | 描述 |
|------|------|
| `review_status` | 最终判定（有伪造/待确认/截图/无伪造） |
| `forgery_score` | 整体伪造风险（0-100） |
| `tamper_index` | 复合篡改指数（0-100） |
| `tamper_evidence_count` | 触发的证据信号数量 |
| `metadata_inspection` | EXIF、软件标签、AIGC元数据 |
| `visual_inspection` | 亮度、饱和度、调色板特征 |
| `local_feature_inspection` | 特征密度、集中度 |
| `screenshot_inspection` | 屏幕比例、边缘/文本/纯色区域指标 |
| `document_tamper_inspection` | 纸张区域分析、可疑块、LBP、梯度、噪声、ELA |
| `risk_labels` | 快速决策的分类标签 |
| `findings` | 所有人类可读的检测发现 |

## 依赖

- Python 3.8+
- Pillow
- NumPy

## 适用场景

本技能面向电子数据取证中的图像真伪初筛与篡改线索发现，适合在实验室受理、现场快速勘验、网络取证溯源、舆情核查等阶段使用。

### 典型业务场景
- 举报、投诉、诉讼、仲裁中的聊天截图、转账截图、合同扫描件、票据照片真伪初筛。
- 诈骗、敲诈勒索、虚假宣传、网络谣言案件中，对当事人提交的图片进行是否编辑、拼接、AI 生成的辅助判断。
- 电子数据固定后，对导出的图片文件、网页图片、邮件附件、即时通信附件进行批量风险排序。
- 从流量包、镜像文件、内存镜像或隐蔽信道中恢复出的可疑图像文件，在重组后进行图像层取证。
- 对 AIGC 图片、深度伪造图片、修图软件输出图片进行元数据与视觉特征层面的线索筛查。

### 适合处理的输入
- 本地原始图片文件，优先使用只读副本或哈希固定后的工作副本。
- 可直接访问的 URL 图片，需同时记录响应头、抓取时间、来源页面与下载工具。
- 从聊天记录、邮件、压缩包、磁盘镜像中提取的图片文件。
- 从网络流量或 ICMP 隐蔽信道中重组出的图片碎片或可疑二进制文件。

### 结果定位
- 输出为风险筛查结论，不直接等同于司法鉴定意见。
- 有伪造、待确认、截图、无伪造四类状态用于分流人工复核优先级。
- 对高价值案件，应结合原始介质、提取笔录、哈希值、元数据、人工图像检验和第三方工具进行交叉验证。

### 慎用或不宜单独下结论的场景
- 图片经过社交平台、即时通信工具多次压缩，EXIF 丢失且压缩伪影严重。
- 原图本身低分辨率、强逆光、运动模糊、严重降噪或扫描质量差。
- 需要精确到像素级的篡改区域定位、签章同一性认定、笔迹鉴定或法庭科学级同一认定。
- 仅凭单一指标，例如仅凭无 EXIF、仅凭 ELA 异常或仅凭纹理不平滑，就作出最终真伪结论。

## D2-04 输入输出说明

### 输入说明
- 检材路径：支持本地文件路径或可访问 URL。取证流程中应优先传入固定后的工作副本，避免直接读取原始检材。
- 输入来源记录：应记录文件名、文件大小、介质编号、提取路径、下载时间、URL、HTTP 响应头、聊天会话、邮件 Message-ID 或流量五元组。
- 网络流量来源：若图片来自流量还原或隐蔽信道，应先完成载荷提取、会话分组、排序重组和文件头校验，再将通过校验的重组文件作为输入。
- 完整性校验：对每个输入文件计算 MD5 与 SHA256，建议同时记录文件路径、哈希值、命令输出和取证人员。

### 输出说明
- review_status：分流结论。有伪造表示存在强篡改信号；待确认表示存在可疑信号但需人工复核；截图表示符合干净截图特征；无伪造表示未发现显著异常。
- forgery_score：整体伪造风险分，用于排序和阈值管理，不应作为唯一证据。
- tamper_index 与 tamper_evidence_count：反映触发证据信号的数量与强度，需结合 findings 逐条解释。
- metadata_inspection：记录 EXIF、编辑软件关键词、AIGC 标签、内容溯源字段。
- document_tamper_inspection：记录纸张区域、纹理一致性、LBP、梯度、噪声和 ELA 等文档类篡改线索。
- findings：人类可读的发现摘要，适合写入勘验笔录或初检报告。

### 证据链与结果解释
- 检测前应保留原始文件只读状态，检测过程中不得覆盖、重命名或修改原始检材。
- 对 URL 图片，应保存抓取命令、响应头、页面快照和下载文件哈希。
- 对 ICMP 等隐蔽信道来源，应保存筛选规则、导出 payload、拼接规则、重组文件哈希和验证过程。
- 输出为有伪造或待确认时，应列出触发的具体字段和证据，说明可能的误报来源，例如微信压缩、截图重编码、美颜、HDR、扫描摩尔纹。
- 输出为无伪造时，应表述为未发现显著异常，而非绝对真实。

## 使用步骤

### 1. 受理与检材固定
- 登记案件编号、检材编号、来源、提交人、接收时间和存储位置。
- 对原始文件进行只读保护，计算 MD5 与 SHA256，生成工作副本用于检测。
- 若检材来自网页或聊天链接，先固定页面、响应头、账号信息和下载过程，再保存本地文件。

### 2. 判断图片来源并做必要恢复
- 本地文件：确认扩展名与实际文件头一致，避免将改名文件直接当作图片。
- 聊天或邮件附件：提取附件原始包、会话记录和传输时间，注意平台压缩会削弱 EXIF 与 ELA 信号。
- 流量或隐蔽信道来源：先筛选可疑协议并重组载荷。以 ICMP 隐蔽信道为例，按以下流程处理：
  1. 筛选 ICMP Echo Request 与 Echo Reply，即 icmp.type 为 8 或 0 的数据包。
  2. 导出 payload，并记录帧号、时间、源 IP、目的 IP、ICMP ID、序列号。
  3. 按会话和序列号排序，根据案件规则拼接 payload 的首字符、固定偏移片段或完整字符串。
  4. 验证重组结果是否为外传数据或常见图像文件头，例如 JPEG 的 FFD8FF、PNG 的 89504E47。
  5. 将可重组为图片的结果保存为独立文件，计算哈希后再送入本技能检测。

示例命令：
```bash
tshark -r case.pcap -Y 'icmp.type==8 or icmp.type==0' -T fields -e frame.number -e frame.time_epoch -e ip.src -e ip.dst -e icmp.id -e icmp.seq -e data.data > icmp_payload.tsv
```

### 3. 执行图像伪造检测
```bash
python scripts/detect.py <图片路径或URL>
```
- 对批量检材，建议逐文件执行并将 JSON 结果落盘，文件名与检材哈希关联。
- 对 URL 输入，应同步保存下载过程与响应头，避免仅依赖脚本抓取结果。

### 4. 结果判读与阈值建议
- review_status 为有伪造：检查 findings 中是否存在强信号，例如编辑软件标签、AIGC 签名、局部纹理断裂、ELA 明显不一致、噪声分布异常。
- review_status 为待确认：优先人工复核，重点查看元数据、压缩伪影、LBP、梯度和文档区域可疑块。
- review_status 为截图：结合宽高比、边缘密度、文本行比例和纯色区域判断是否为原始截图；截图不等于未篡改，仍需确认是否有二次编辑。
- review_status 为无伪造：记录为未发现显著异常，保留检测输出和哈希，便于复核。

### 5. 复核与交叉验证
- 对高风险结果，至少使用两类独立信号交叉验证：元数据、压缩特征、纹理一致性、噪声一致性、ELA。
- 若怀疑 AI 生成，重点检查 AIGC 元数据、内容溯源标签、纹理过度平滑、局部特征分布异常；但不要仅因无 EXIF 就认定伪造。
- 若怀疑文档或纸质件篡改，重点复核纸张区域分割、文本行波动、LBP 相邻块差异、梯度方向不一致和重新编码 ELA。
- 必要时使用 ExifTool、FotoForensics、Ghiro、Photoshop 或专业图像鉴定工具进行人工复核，并在报告中说明工具与版本。

### 6. 常见陷阱与规避
- 微信、QQ、微博等平台二次压缩会破坏原始 EXIF 并产生压缩伪影，应优先调取原图或原始附件。
- ELA 对保存参数敏感，单张图的 ELA 异常只能作为线索，不能作为唯一结论。
- 美颜、HDR、夜景降噪会造成纹理平滑和噪声不一致，应结合拍摄设备、场景和多个特征判断。
- 截图、屏幕翻拍、扫描件天然存在边缘锐化、摩尔纹和纯色区域，不应简单视为伪造。
- 对隐蔽信道恢复出的图片，若文件头损坏或载荷缺失，应先标记为不可完整重组，再评估是否具备图像检验条件。

### 7. 报告归档
- 归档原始检材哈希、工作副本哈希、检测命令、脚本版本、依赖版本、JSON 输出、人工复核记录和结论。
- 报告中应写明：检材来源、固定方式、检测方法、触发证据、误报可能、结论边界。
- 若结论用于诉讼或仲裁，应提示委托方本技能属于辅助筛查，需由具备资质的人员或机构出具正式鉴定意见。
